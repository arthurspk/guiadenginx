## :dart: O guia para alavancar a sua carreira

> O Nginx é um servidor web, proxy reverso e balanceador de carga open source criado por Igor Sysoev em 2004 e hoje mantido pela F5 — a espinha dorsal de boa parte da internet moderna, presente desde os maiores sites do mundo até a API mais simples em produção, conhecido pela performance sob alta concorrência e pelo baixo consumo de memória. Ele combina muito bem com stacks modernas: na frente de containers Docker/Kubernetes, terminando SSL/TLS, servindo cache de conteúdo estático ou balanceando carga entre várias instâncias de uma aplicação. Este guia reúne documentação oficial, cursos gratuitos e pagos, livros, ferramentas, projetos práticos e um capítulo dedicado a usar IA na prática com Nginx — tudo verificado e organizado para quem quer sair do zero até colocar um proxy reverso com HTTPS e balanceamento de carga rodando em produção.

## 🚀 Por onde começar

> Uma trilha resumida para sair do zero até ter um proxy reverso com HTTPS no ar:

1. Entenda o que é um servidor web e um proxy reverso lendo o [Beginner's Guide oficial](https://nginx.org/en/docs/beginners_guide.html).
2. Instale o Nginx localmente seguindo o [tutorial oficial do Ubuntu 24.04 (DigitalOcean)](https://www.digitalocean.com/community/tutorials/how-to-install-nginx-on-ubuntu-24-04).
3. Aprenda a estrutura dos arquivos de configuração na seção [Configuration File's Structure (Beginner's Guide)](https://nginx.org/en/docs/beginners_guide.html#conf_structure).
4. Hospede mais de um site no mesmo servidor com [server blocks](https://www.digitalocean.com/community/tutorials/how-to-set-up-nginx-server-blocks-on-ubuntu-22-04) (o "virtual host" do Nginx).
5. Habilite HTTPS gratuito com [Certbot](https://certbot.eff.org/instructions?ws=nginx&os=ubuntufocal), seguindo o [passo a passo da DigitalOcean para Ubuntu 24.04](https://www.digitalocean.com/community/tutorials/how-to-secure-nginx-with-let-s-encrypt-on-ubuntu-24-04).
6. Entenda proxy reverso, cache e balanceamento de carga no [guia da DigitalOcean sobre Nginx HTTP Proxying, Load Balancing, Buffering e Caching](https://www.digitalocean.com/community/tutorials/understanding-nginx-http-proxying-load-balancing-buffering-and-caching).
7. Quando o site estiver estável, teste sua configuração HTTPS no [SSL Labs](https://www.ssllabs.com/ssltest/) e adicione uma camada extra de segurança com o [ModSecurity para Nginx](https://github.com/owasp-modsecurity/ModSecurity-nginx).

- [ngx_http_rewrite_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_rewrite_module.html) — Referência completa das diretivas `rewrite`, `if` e `return` para reescrita de URLs.
- [ngx_http_ssl_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_ssl_module.html) — Referência do módulo que habilita HTTPS/TLS no Nginx.

- [ngx_http_upstream_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_upstream_module.html) — Referência do módulo de balanceamento de carga entre servidores upstream.

- [ngx_http_limit_req_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html) — Rate limiting: como limitar a taxa de requisições por cliente.
- [ngx_http_limit_conn_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html) — Como limitar o número de conexões simultâneas por chave (ex.: IP).

- [ngx_http_log_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_log_module.html) — Como configurar e formatar os logs de acesso.
- [ngx_http_map_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_map_module.html) — Cria variáveis condicionais a partir de outras variáveis, muito usado em configurações avançadas.
- [ngx_http_fastcgi_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_fastcgi_module.html) — Referência do módulo usado para servir aplicações PHP (FastCGI) atrás do Nginx.
- [ngx_http_v2_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_v2_module.html) — Como habilitar suporte a HTTP/2.
- [ngx_http_v3_module — documentação oficial](https://nginx.org/en/docs/http/ngx_http_v3_module.html) — Como habilitar suporte a HTTP/3 e QUIC.

## 🤖 IA na prática

O Nginx tem uma sintaxe de configuração própria (`nginx.conf`, blocos `server`/`location`, diretivas de `rewrite` e `proxy_pass`) que é justamente o tipo de texto estruturado e cheio de regras específicas em que um assistente de IA ajuda bastante — desde que você confira o resultado com o próprio Nginx (`nginx -t`), não apenas confiando no que a IA disse.

**Para aprender**
- Cole um trecho do seu `nginx.conf` e peça para a IA **explicar linha por linha** o que cada diretiva faz — é mais rápido que caçar cada uma na documentação oficial.
- Peça para a IA **gerar uma regra de `rewrite` ou um bloco `location`** a partir de um exemplo em português (ex.: "redirecionar tudo de `/blog/antigo/*` para `/artigos/*` com 301") e depois valide testando no servidor.
- Peça exercícios práticos: "monte um cenário com dois domínios fictícios atrás de um proxy reverso e peça para eu escrever a configuração, depois corrija o que eu errar".

**Para trabalhar**
- Use assistentes de código como [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar blocos `server`, regras de `proxy_pass` e configurações de `upstream`/`ssl` a partir de uma descrição em linguagem natural.
- Cole uma mensagem de erro do log (`error.log`) e peça à IA para explicar a causa provável e sugerir a diretiva que resolve — mas sempre confirme na documentação oficial antes de aplicar em produção.
- Terminais com IA embutida, como o [Warp](https://www.warp.dev/), ajudam a lembrar comandos de administração do Nginx (`nginx -s reload`, `nginx -t`, `systemctl`) sem sair do terminal.
- **Sempre** rode `nginx -t` depois de qualquer mudança de configuração sugerida por IA, antes de recarregar o serviço (`nginx -s reload`) — é a forma mais rápida de pegar um erro de sintaxe antes que ele derrube o site.

**Limites e boas práticas**
- IA erra em detalhes específicos de versão (diretivas de módulos que exigem compilação extra, por exemplo) e pode misturar sintaxe do Apache com a do Nginx — são conceitos parecidos, mas a sintaxe é bem diferente. Confirme sempre na [documentação oficial](https://nginx.org/en/docs/).
- Nunca cole senhas, certificados privados ou dados de clientes reais em uma ferramenta de IA sem verificar a política de privacidade da sua empresa.
- Regras de segurança geradas por IA (rate limiting, ModSecurity, bloqueios de IP) devem ser testadas antes de ir para produção — um bloqueio mal configurado pode derrubar o acesso legítimo ao site.
- Entenda o que você está aplicando: em um servidor de produção, cada diretiva aceita é sua responsabilidade.
